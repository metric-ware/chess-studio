Edit (studio/edit.py) is a timeline drawing into a Frame (a Cairo surface over a premultiplied BGRA NumPy buffer): the scene registered with edit.scene(shot, cuts), then layers registered with at(t0, t1) in order, the top caption shade (shade=px), vignette, captions. Grain was removed to preserve the solid black background. Frames are pure functions of time, so preview workers, render workers and motion-blur samples agree. Default size is 1080x1350 (4:5) at 60fps. Music is one song with segments spliced back to back; its beats and chosen drop are mapped to edit time, beat(t, k) steps through beats, and to_edit(x) converts a song time.
Motion blur (Edit._expose) is a 180-degree shutter with adaptive sampling: it renders the shutter's two ends and keeps doubling the samples (2, 3, 5, 9, 17, 33) while any neighbouring pair still differs by more than 40 in the biggest 8x8-block mean absolute difference, so a nearly still frame costs two renders and a camera whip gets up to 33. It replaced a fixed 8-sample shutter in the edit script (about 9 minutes per render) and, before that, a 2-sample shutter that split fast pieces into two visible copies. Samples never cross a time listed in cuts. render(draft=True) / `render --draft` uses one sample per frame and a veryfast CRF 23 encode into build/<slug>_draft.mp4 (about 40s for an 18s edit) for checking motion and timing; `preview` accepts start:end:step ranges for filmstrips.
Rendering forks workers explicitly because Python 3.14's forkserver cannot pickle script closures. studio/__init__.py pins OpenBLAS/OMP/MKL to one thread before NumPy loads, and OpenCV to one thread: the 2.5D projection uses matrix products, and a BLAS thread pool inherited across fork deadlocked every worker. Preview and render use ProcessPoolExecutor with the fork context so a dead worker raises instead of silently hanging a Pool.map. Render reports completed segments and uses the CPU count available to the process. A near-camera piece once requested a sprite tens of thousands of pixels wide; draw_board now culls pieces closer than 0.8 squares to the camera and caps sprites at 1024px. Each worker pipes frames to x264 (CRF 15), segments concatenate without re-encoding, and build/<slug>/render/ is deleted after export, so build/ retains only previews and drafts. Final muxing happens in render scratch and atomically replaces the destination after success, preserving the existing export on failure. CLI commands select the latest modified edits/*.py by default; render accepts a slug/path, preview and still use --edit to select one. Preview with no times draws eight frames across the duration, and still creates its output directory.
export_clean strips container metadata, chapters, creation times, encoder strings, and the x264 settings SEI (filter_units remove_types=6). FFmpeg still writes VideoHandler/SoundHandler hdlr names under bitexact even when handler_name is set empty, so the export zeroes those name bytes in place, which keeps every box size intact. Only the standard isom brand tags remain. BT.709 conversion uses scale out_color_matrix plus setparams because output tags alone were insufficient in the installed FFmpeg.
A 4:5 video in the full-screen Shorts player is centered with bars, so the top bar falls outside the picture. Approximately, the right action rail covers x 945-1080 from y ~595 down and the bottom title area covers the last ~75px (derived from the 9:16 guides: top 0-150, rail x945-1080/y880-1720, bottom y1560-1920). There is no automated check for this.
